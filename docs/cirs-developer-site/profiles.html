Feature Selection

Understand the profile before you debug the behavior.

Auth provider, token mode, MFA mode, media storage, and record deletion are feature-selected. Valid combinations are enforced at runtime in development and at build time in production.

Core rule Profiles are not cosmetic

They change auth flow, token semantics, MFA behavior, storage behavior, and what runtime secrets are actually required.

Development flexibility Runtime switching allowed

In development, you can move between local and Supabase-backed combinations by changing the active feature variables and restarting the app.

Production rule Build-time locking only

Once the production build is generated, the selected feature combination is frozen until the next build.

Feature Groups

Auth provider

Choose between local auth and Supabase-backed auth.

Token mode

Use app JWT for local auth or Supabase JWT for Supabase auth.

MFA mode

Use local TOTP, Supabase TOTP, or disable only where the deployment allows it.

Storage and deletion

Media storage and archive versus hard-delete are also profile-controlled.

Feature Matrix

Feature Environment variable Options Default in development
Auth provider FEATURE_AUTH_PROVIDER local, supabase local
Token mode FEATURE_TOKEN_MODE app-jwt, supabase-jwt app-jwt
MFA mode FEATURE_MFA_MODE disabled, local-totp, supabase-totp local-totp
Media storage FEATURE_MEDIA_STORAGE disabled, supabase-storage disabled
Record deletion FEATURE_RECORD_DELETION hard-delete, archive archive

Constraints

  • Supabase JWT requires the Supabase auth provider.
  • Supabase TOTP requires Supabase JWT mode.
  • MFA disabled is blocked in production when privileged roles exist.
  • Invalid combinations fail the build or crash at startup.

If behavior looks impossible, check the profile first. Many auth and session differences are profile-driven, not code regressions.

Recommended Profiles

Development Local

Local auth, app JWT, local TOTP

Best for day-to-day backend work, tests, and non-Supabase flows.

Development Supabase

Supabase auth, Supabase JWT, Supabase TOTP

Best for integration checks and validating Supabase-backed flows before production.

Production Supabase Auth

Supabase auth with archive-safe records

Recommended baseline when media storage is still disabled.

Production Full Supabase

Supabase auth plus media storage

Use when storage bucket, access mode, and upload controls are production-ready.

Switching In Development

FEATURE_AUTH_PROVIDER=supabase \
FEATURE_TOKEN_MODE=supabase-jwt \
FEATURE_MFA_MODE=supabase-totp \
FEATURE_PROFILE_NAME=development-supabase \
npm run dev

You can also place the full set of FEATURE_* values in .env.development and restart the server.

Production Locking

  1. Read FEATURE_* from env or build inputs.
  2. Validate that the selected combination is legal.
  3. Write the locked output to src/generated/productionFeatureProfile.ts.
  4. Compile with TypeScript and run using the locked profile.
